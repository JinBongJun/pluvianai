# Weekly Channel Operations

## Purpose

This document defines the weekly operating rhythm for content, outreach, and feedback collection.

The goal is not to broadcast the same message everywhere.
The goal is to use each channel for a different job.

## Channel Priority

1. Reddit
2. LinkedIn
3. X
4. Indie Hackers
5. dev.to

## Core Rule

- do not copy-paste the same post across channels
- keep one core message, but adapt the framing to the channel
- prioritize real conversations over reach

## Channel Roles

### Reddit

- role: question-driven discovery
- goal: learn how people currently handle deploy safety, replay, repeated runs, and flaky behavior
- format: question post, text-first, low-promo

### LinkedIn

- role: direct conversation
- goal: get replies, follow-up conversations, and demo or pilot interest
- format: short personalized DM

### X

- role: short-form amplification
- goal: test sharp phrasing and drive profile visits or replies
- format: compact statements and questions

### Indie Hackers

- role: founder/operator reflection
- goal: validate startup/founder pain and share what changed in the team’s thinking
- format: short retrospective with one clear lesson

### dev.to

- role: long-term credibility asset
- goal: create reusable content for search, trust, and future sharing
- format: structured post explaining one concrete problem and one practical takeaway

## Weekly Rhythm

### Monday

- review last week’s comments, replies, and notes
- identify the best-performing phrase
- decide the one key question for this week

### Tuesday

- publish `1` Reddit post
- engage in comments for the first `30-60` minutes

### Wednesday

- send LinkedIn DM to `10-20` people
- prioritize people with visible production or shipping responsibility

### Thursday

- publish `1` X post
- use language taken directly from Reddit comments or DMs when possible

### Friday

- publish `1` Indie Hackers post or a second X post
- use founder/operator framing, not infrastructure jargon

### Weekend

- draft or refine one dev.to post if enough material has accumulated
- this does not need to happen every week

## Minimum Weekly Output

- Reddit: `1`
- LinkedIn DMs: `10-20`
- X: `1-2`

## Optional / Lower Frequency

- Indie Hackers: every `1-2` weeks
- dev.to: every `2-4` weeks

## Message Flow

Use this sequence:

1. ask the question on Reddit
2. collect pain language and current workflows
3. reuse the strongest language in LinkedIn DMs
4. compress the sharpest line into X
5. summarize the learning in Indie Hackers or dev.to

## Good Signal

- people explain their current process
- people mention replay, repeated runs, or workflow instability
- people ask follow-up questions
- people agree to continue the conversation

## Weak Signal

- likes or impressions without replies
- generic agreement without operational detail
- curiosity without follow-up intent

## Current Strong Phrases

- `final output is a lagging indicator`
- `one successful run is meaningless for agents`
- `path consistency`
- `tool call stability`
- `real failures, not synthetic ones`
- `pre-deploy evaluation vs production observability`

## Review Questions

At the end of each week, answer:

- which channel produced the best conversations?
- which phrase got the strongest reaction?
- who replied: founder, engineer, or operator?
- did anyone ask for more?
- what should be reused next week?
